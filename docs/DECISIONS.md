# Decisions

- The six core data contracts are frozen v1. `FailureEvent.detail` uses `Field(default_factory=dict)` so instances do not share mutable state; this is the only deviation from the SPEC definitions.
- `Replay`, `ReplayFrame`, `CampaignResult`, and `BenchmarkResult` are additive contracts. The top-level replay, campaign, and benchmark models forbid unknown fields and label data with `source`.
- Replay frame coordinates use eight ordered xyz points. Torque and velocity ratio index `j` maps to link point `j + 1`; link point 0 is uncolored.
- Campaign strategy values are `nemotron`, `random`, and `cmaes`. Phase 7 events have a monotonic `seq`, UTC `ts`, a fixed event type, and a type-validated `data` payload. `campaign_done` separates `status` (`completed`, `cancelled`, `error`, `token_cap`, or `no_failures_found`) from `stop_reason` (`budget`, `clusters`, `token_cap`, or `none`); budget exhaustion is not a status.
- Benchmark means and standard deviations use population statistics. Missing per-seed first failures stay `null` in raw data and contribute `budget + 1` to the aggregate; the mean is marked as a lower bound when some seeds have no failure. Curves must have `budget` entries, per-seed results must have `seed_count` entries, and strategy names must be unique.
- Settings read process environment variables only. Keys, base URL, and model IDs default to empty strings; token cap defaults to 400000 and demo mode to false. Local API startup loads `.env` through `uv run --env-file .env`; if `.env` is absent, uv exits before starting the app. CI and `make check` do not use an env file.
- Hatchling is the only build-system dependency; it builds the `src/omnisim` package for installation.
- Mock fixtures use `source="mock"`, envelope version `mock-0`, `https://mock.invalid/` evidence URLs, and quotes prefixed with `[mock]`.
- The SPEC repo layout is used because `docs/ARCHITECTURE.md` is absent.
- LLM usage is stored in SQLite at `data/llm_usage.sqlite3`, keyed by UTC date and role. A SQLite write transaction holds request admission through usage recording, so a response can take usage over the cap by at most that response. Missing usage is recorded as zero and logged.
- LLM callers use `chat_json` with `fast`, `deep`, or `ultra` roles. Model resolution accepts a configured ID only when it is listed and is an NVIDIA Nemotron model, then uses the role-specific Nemotron preference order. Missing NVIDIA Nemotron models raise `LLMUnavailable`; no other model family is selected.
- Content candidates are validated from first to last; `reasoning_content` candidates are validated from last to first. Schema or JSON failures use the requested repair retries. Transport timeouts, connection errors, 429, and 5xx responses get one retry after 0.25 seconds. SDK retries are disabled and requests use a 30-second timeout.
- A response ending with `length` doubles `max_tokens` for the next output attempt, capped at 8192 tokens. Each HTTP request attempt, including model listing, is written to `data/llm_calls.jsonl` without prompt contents or credentials. Model listing is not charged against the token budget.

## Phase 3: simulation core

1. `PandaSim` owns one DIRECT client, uses `ScenarioParams.seed` for its local NumPy generator, supports context management, and closes idempotently. The frozen schemas remain unchanged.
2. Sensor noise affects measured arm position only. The controller uses `q_des = q_ref + 0.25 * (q_ref - q_meas)`; the gain is fixed for this phase.
3. IK and reference FK are planned once per episode on a separate DIRECT client. IK null-space inputs contain the seven arm joints and two open fingers; the arm uses the first seven results. The kinematics call needs nine values, and `getLinkState` after `resetJointState` needs `computeForwardKinematics=1`.
4. The pose sequence is approach `(0.4, -0.15, 0.28)`, pick `(0.4, -0.15, 0.2)`, lift to the approach height, and place at `(0.4, 0.15, 0.2)` metres, using a fixed tool-down orientation. Segments use min-jerk profiles with stop-and-go boundaries. `T0=2.5s`, so the slowest `speed_scale=0.5` reaches the place reference by 5 seconds and holds it for the remaining episode time.
5. The push acts in world +Y at the hand COM for `[push_time_s, push_time_s + 0.1s)`. Apply it at each 240 Hz substep because PyBullet clears external forces after every simulation step.
6. Scale mass and diagonal inertia together on links 0–8 before adding payload at the hand COM. Model payload inertia as a sphere with radius `0.05m`, added equally to each diagonal.
7. `jointDamping` is applied to arm joints 0–6. A fixed-seed comparison at 0 and 5 produced maximum differences of 0.000292 rad in position, 0.00145 rad/s in velocity, 8.29 N·m in applied torque, and 0.000114 m in end-effector position under POSITION_CONTROL.
8. Telemetry arrays are preallocated float64. Replay link point 0 is the base load position and points 1–7 are links 0–6; joint ratio index `j` maps to point `j+1`. The Jacobian metrics use the 3×7 arm slice from a nine-DOF calculation. Contact count is the number of distinct non-base robot links in contact.
9. Downsampling accepts only positive FPS values dividing 60, selects every `60/fps` tick without interpolation, and validates each frame as a `ReplayFrame` with empty flags. The Phase 4 runner adds replay metadata.
10. `deterministicOverlappingPairs=1` is enabled with the locked PyBullet 3.2.7. `render.py` remains deferred until a rendering dependency is approved. All simulation ranges and payload assumptions are not hardware tolerances.

## Phase 4: detectors and runner

11. Risk is the largest normalized detector term, capped at 10: torque is the largest five-tick window minimum divided by 0.95; joint margin is 0.02 rad divided by the smallest observed margin (with a 1e-6 rad floor); velocity is the largest ratio divided by 1.0; tracking is the largest end-effector error divided by 0.05 m for samples at or after 0.5 s; singularity is the largest `jac_cond` divided by 1e3; collision and instability are binary terms. An event raises its term to at least 1.0. A non-event can still have risk below 1.
12. Detector thresholds are inclusive: torque ratio >= 0.95 for five consecutive ticks, velocity ratio >= 1.0, joint margin <= 0.02 rad, tracking error >= 0.05 m after the settle cutoff, and condition number >= 1e3. Event timestamps use the zero-based tick divided by 60; a torque event is timestamped at the first tick of its qualifying five-tick window. The singularity detector treats larger condition numbers as higher risk; the SPEC has no section 8 defining this rule. Oscillation detection is deferred.
13. A non-finite telemetry sample or derived detector value marks instability. Non-finite values are excluded from metric reductions; empty reductions return zero so risk, metrics, event severities and details stay finite. The divergence guard fires at velocity ratio >= 10.0; this value is provisional and uncalibrated, and is not a hardware limit.
14. `EpisodeRunner` uses a reusable spawn process pool for `workers > 1` and serial execution otherwise. Results retain input order. The simulation checks its deadline each control tick; the parent waits through a one-second grace, terminates and rebuilds a pool that does not return, and reports unfinished work as `EpisodeError` with `WorkerTimeout`. Worker exceptions and serial `OSError`, timeout and PyBullet errors are returned as frozen `EpisodeError` values. A supplied shield receives a parameter copy; `EpisodeResult.params` retains the original values. The frozen result contract has no separate shield-status field, so callers know shield status from whether they supplied a shield.
15. Saved replays are validated as `Replay`, use `source="live"`, compact JSON and six-decimal rounding. At each frame, flags are the OR of detector masks for the ticks represented by that frame. Phase 7 saved hero runs use `source="recorded"`.
16. The nominal seed-17 maximum tracking error for samples at or after 0.5 s measured 0.0489868 m, above the 0.03 m acceptance gate. Keep the 0.5 s cutoff and current gains unchanged until Phase 3 gain retuning is evaluated; only consider a stopped-reference grace period if retuning fails. All detector values remain simulation policy, not verified operating limits.

## Phase 5: knowledge agent

17. Tavily cache identity is the SHA-256 of canonical JSON containing the operation and every request parameter. Search results cache as one operation; extracted page text caches by URL and extract depth. Cache files have a schema version and are replaced atomically.
18. Panda specification and error searches are limited to `franka.de`, `frankaemika.github.io`, and `docs.franka.de`, with result-domain filtering. `github.com` may appear only in known-issue corroboration results and never supplies spec evidence.
19. Evidence is verified only when its normalized quote is long enough, appears in the fetched page, and contains its value. This does not assert that the quote supports the claim. Only verified values may feed the envelope, URDF comparison, or error mapping.
20. Limit evidence claims use `joint {n} {quantity}`, with one-based documentation joint numbers and `quantity` equal to torque, velocity, lower, or upper. The URDF comparison maps documentation joint `n` to URDF index `n - 1`.
21. `Mismatch` and `ErrorMapping` are additive schema contracts. `ErrorMapping` is an advisory documented analogue, not a statement that the robot would raise that error.
22. Spec extraction uses separate limits and error-taxonomy `chat_json` calls. Model drafts contain page IDs and quotes; code resolves source URLs and computes verification. An extraction `LLMError` propagates without returning a partial spec.

## Phase 6: adversary and benchmark harness

23. Scenario bounds come from the `ScenarioParams` field constraints. Baseline strategies operate in normalized `[0, 1]` coordinates; `latency_ticks` is rounded to an integer. CMA-ES uses `x0=0.5`, `sigma0=0.3`, the library's default population, no restarts, and a deterministic nonzero seed. It maximizes risk by passing `-risk` to `tell`; `EpisodeError` receives zero risk.
24. Every strategy sees the same simulation seed at each benchmark index. A simulation seed is derived from the benchmark seed modulo `2**32` and the simulation index with `numpy.random.SeedSequence`, independent of strategy and worker count.
25. The Nemotron adversary uses the fast `chat_json` role and `adversary_system.md` at temperature 0.7 and 4096 output tokens. It ignores model-supplied seeds, rejects non-finite recognized fields, clamps to schema bounds, rounds latency, and removes candidates within normalized L-infinity distance 0.001. It uses the last 12 successful trials and a failure-kind/joint count with best risk; it receives no documentation evidence or detector thresholds. Missing proposals split evenly between exploitation and exploration, with an odd slot assigned to exploitation when successful history exists.
26. Benchmark cache filenames contain hashes of the full request identity, salt, prompt-file hash, and resolved model ID. Cache files store only the parsed response, token usage, resolved model ID, salt, and prompt-file hash; request text is not stored. Each entry is replaced atomically. Replay-only mode makes no model-list or completion request, fails on a missing request, and rejects multiple model IDs among valid entries with the same salt and prompt hash.
27. Raw benchmark JSONL starts with a metadata header, has one row per simulation, and ends with a count summary. The header records model ID when Nemotron made a call, temperature, token limit, prompt hash, detector configuration, PyBullet package version, budget, seeds, strategy settings, salt, and dev/reporting mode. The result JSON uses the frozen `BenchmarkResult` contract.
28. A seed range that intersects 0 through 99 is a dev run as a whole. Dev runs use `data/dev/benchmark_llm_cache/`, `data/dev/benchmark_raw.jsonl`, and default `data/dev/benchmark.json`; those paths are ignored. Every other seed range is a reporting run and uses `data/benchmark_llm_cache/`, `data/benchmark_raw.jsonl`, and default `data/benchmark.json`. Custom outputs must remain in the matching data directory.
29. Raw and result files are written to sibling temporary files and replaced only after all requested strategies and seeds finish. A budget stop or run abort leaves the previous raw and result files untouched. Completed cache entries can remain after an aborted run for later reuse.
30. Git leaves the three reporting benchmark paths visible and ignores `data/dev/` and other LLM caches. The §11 amendment for the reporting benchmark cache exception is supplied separately for manual application.
31. Phase 7 diagnosis builds one six-decimal measured-facts object and uses the same values in the prompt and numeric-claim validation. Only verified evidence IDs and supplied qualitative known-issue IDs resolve to report references; code supplies real-error mappings and corroborating URLs. Diagnosis uses the deep Nemotron role at temperature zero with one repair attempt, and numeric prose claims are rejected unless a measured fact supports them.
